## Priority 1 — critical security

- [x] 1.1 Secure `place_order` / `quote_order`. All prices, stock, coupon, shipping (base + per-kg), COD fee and tax are computed in the DB inside one transaction. Rows are locked `FOR UPDATE` and stock is checked with a named error; the order and its items are inserted together, stock is reduced once and coupon uses are counted. The old `decrement_order_stock()` is dropped, so stock can't be reduced twice. `placeOrder` now only calls the RPC with ids and quantities; a `quoteOrder` server function is added for Task 2.5. Files: `supabase/migrations/20260923100000_secure_place_order.sql`, `src/lib/account.functions.ts`, `src/routes/checkout.tsx`, `src/integrations/supabase/types.ts`.
  - Decisions to confirm: (a) new orders get `payment_status = 'pending'`, because the enum has no `unpaid` yet; Task 3.1 adds the new payment states. (b) The COD fee stays PKR 150, now fixed in SQL (`c_cod_fee`); it could become a store setting. (c) Per-kg shipping uses exact weight: `base + round(kg × per_kg_rate)`. **If any existing zone has `per_kg_rate > 0`, shipping prices go up once this migration is applied.** Check zones in admin Settings first. (d) A free-shipping coupon removes delivery but not the COD fee. (e) The shipping zone is matched from the address city on the server. The client can't pick a zone, because that would let it choose the cheapest one. (f) A variant line checks and reduces only the variant's stock; the old code also reduced the parent product.
